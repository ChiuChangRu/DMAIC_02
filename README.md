# 檢體針噪音量測工具

瀏覽器端即時噪音量測工具（HTML + Web Audio API），用於評估檢體針觸發時的**相對**聲音大小。

線上使用：https://chiuchangru.github.io/DMAIC_02/

## 功能
- 即時 RMS 讀值 + Peak Hold（dBFS）
- 校正功能：輸入已知音壓（如聲學校正器 94 dB @ 1 kHz）換算近似 dB SPL
- 擊發自動觸發記錄（可調 dwell time 與再觸發間隔）+ 手動記錄，可匯出 CSV
- 記錄圖譜：每筆記錄畫成長條圖，同標籤同色，可直接比較不同針的相對音量

## 擊發波形與機構判讀

每次觸發除了記錄峰值，也會擷取擊發**前後**的完整波形（預設 -60 ~ +300 ms）。
與一般波形圖不同，「擊發波形」面板裡**每一筆記錄各自畫成一張獨立的小圖，彼此不疊加**，
縱軸也不是原始振幅或 dBFS，而是**相對於這一筆自己峰值的 dB 差距**——
峰值那一刻固定在圖表頂端 = 0 dB，其餘時間點是比峰值低幾 dB。

這樣設計的理由：擊發音量本來就有大有小（不同針、不同角度），
若縱軸用絕對音量，大小聲的波形高度天差地遠，很難比較「衰減得快不快」「有沒有雙峰」；
改成各自以峰值歸零之後，不管原始多大聲，都能直接比對**時間軸上的形狀**。

右上角「顯示範圍 (dB)」控制縱軸往下顯示到峰值下多少 dB（預設 10，即 0 ~ -10 dB），
超出範圍的部分會被裁到圖表底部。擊發密集、波形變化快時可以調大看更多細節。

## 自動裁切時間軸

原本波形固定顯示整段擷取窗（預設 -60~+300ms），但實際訊號常常在幾十毫秒內就衰減完，
剩下一大截是空的平線，把真正有變化的部分（衰減快慢、有沒有二次撞擊）壓縮到圖表一小角，
反而不容易比較。

勾選「自動裁切時間軸」（預設開啟）後，會自動找出訊號**最後一次**衰退到峰值下
「衰退門檻 (%)」以內（預設 90%，即 -20dB）的時間點，乘以 2 倍當緩衝，設成該筆的顯示範圍。
抓「最後一次」而不是「第一次」，是為了不要把在主脈衝衰退完之後才出現的二次撞擊切掉——
那正是這個工具原本要看的東西：如果訊號在衰退完之後、擷取窗結束前又出現明顯的二次波動，
顯示範圍會自動撐大到涵蓋它，不會被誤切。

疊圖比較時，共用的時間軸取「選取的每一筆各自建議的顯示範圍」的聯集——只要選取的幾筆裡
有一筆衰減得比較晚，軸還是會撐到那裡，不會因為別筆訊號早就結束而被截斷；
但也不會被某一筆用不到的長尾平白拉長，讓大家一起被壓縮成一條細線。

取消勾選會顯示原始完整擷取窗（跟擷取前後長度設定一致），適合想確認裁切範圍以外
是否還有東西時使用。

每張卡片右上角有 × 可以個別刪除那一筆記錄（連同記錄表列與圖譜長條一併移除，
不會跳確認框，方便快速丟掉誤觸發或量測失敗的一次）；
標題列右側「全部清除」會清空所有記錄，因為不可逆會先跳出確認框。
這個按鈕跟「觸發記錄設定」面板裡的「清空記錄」是同一個功能，放兩個位置純粹方便，效果相同。

## 放大檢視與疊圖比較

點一下任一張波形卡片會被選取（外框變成青色），選取的內容會放大畫在網格上方的
「比較區」裡，一張圖是放大單看，兩張以上會疊在同一張圖上直接比較差異。
再點一次卡片可取消選取；點卡片右上角的 × 是刪除，不會觸發選取。

疊圖時每一筆仍然各自以自身峰值為 0 dB（不會因為疊在一起就變回絕對音量比較），
時間軸則對齊到實際的觸發瞬間（t=0）——即使兩筆的擷取前/後長度設定不同，
疊起來還是對得準，可以直接比較衰減快慢、有沒有二次撞擊等時間軸上的形狀差異。

疊圖的每一筆用不同顏色區分（跟記錄圖譜的配色邏輯一致，不會因為削波就全部變成同一種紅色，
否則好幾筆同時削波時會疊成同一條線、完全分不出來），線條半透明，重疊處彼此看得穿。
曲線一律畫實線——虛線會沿路徑長度套用「畫一段、空一段」，尖峰剛好落在空隙裡就不會被畫出來，
對這種要看準確波形的工具是缺陷，不能拿來當削波的裝飾用法。

## 削波觸頂比例：分辨單一異常尖峰跟持續性飽和

「有沒有削波」只是是非題，看不出嚴重程度。卡片與圖例上的「⚠削波」旁邊
會標出這一筆在整個擷取窗內有多少比例的時間貼著滿刻度（例如「29% 時間觸頂」）：

- **比例很低（個位數 %）**：通常是單一瞬間的異常尖峰打到頂，訊號其餘時間正常
- **比例偏高（兩位數 %，甚至形成一整段平台）**：代表訊號在類比前級或 ADC
  階段就已經持續性飽和，不是單一異常，而是麥克風輸入音量整體開太大

看到高比例的削波，直接去調低系統的麥克風輸入音量（見上方「使用限制」段落），
而不是只針對單一異常去追機構原因——調高比例的削波，波形形狀已經失真，
再怎麼看都判斷不出真正的機構訊息。

## 調低系統音量後仍然全部削波怎麼辦

Windows 的「音量」滑桿跟麥克風的「加強 / Boost」dB 是**兩個獨立的控制**，
前者調再低，後者沒關的話還是會過載。依序排查：

1. 音效控制台 → 錄製 → 選麥克風裝置 → 內容 → **等級**分頁 → 檢查
   「Microphone Boost」是否被設成 +20dB 或更高，拉到 0 或最低
2. 同一視窗的「**增強功能**」分頁，或裝置管理員裡的驅動進階設定，
   把自動增益、降噪等效果全部關閉——瀏覽器請求 AGC 關閉不代表驅動層
   真的服從，尤其是筆電內建的智慧型音效技術（如 Intel Smart Sound）
   很容易在瀏覽器管不到的那一層自己做動態增益
3. 拉開麥克風與擊發點的**物理距離**：喀嗒聲的瞬間聲壓如果太近，
   可能在訊號進到任何數位設定之前，就已經讓麥克風的類比前級或 ADC
   過載（類比端過載），這是物理限制，只能靠拉開距離免費驗證

三項都排除後如果仍然全部削波，代表這顆麥克風的設計動態範圍
（通常為語音而非瞬間高聲壓的機構聲響最佳化）無法勝任這個量測情境，
需要外接**帶實體增益旋鈕**的麥克風或 USB 音效卡，才能不受系統自動增益
擺佈地手動壓低輸入；若需要可追溯的絕對 dB SPL，才需要升級到
使用限制段落提到的 Class 1 噪音計 + 聲學校正器。

刪除某一筆時若它正被選取，比較區會自動移除該筆並更新畫面。

判讀重點：

- **t=0 之後出現第二個明顯脈衝** — 機構有二次撞擊或彈跳
- **主脈衝衰減到底部（超出顯示範圍）的時間點延後** — 零件鬆動、共振拖尾
- **不同筆之間衰減形狀差異大** — 動作一致性不良（因為都歸零到 0 dB，可直接並排比較）
- **t=0 之前就有訊號** — 觸發閾值設太低，被環境噪音搶先觸發

擷取前／後的長度可在「觸發記錄設定」調整。波形僅存在瀏覽器記憶體中，
CSV 匯出只含數值欄位，重新整理頁面即消失。

### 削波（clipping）

樣本觸及數位滿刻度時，波形會被削平、峰值一律讀成 0.0 dBFS，
不同強度的擊發會變得完全無法區分。發生時：

- 主畫面出現紅色「⚠ 削波 CLIP」徽章（按「重置 Peak Hold」才會清除）
- 該筆記錄的「削波」欄標示 ⚠，圖譜上的長條加紅色頂蓋，CSV 該欄為 Y

**削波的數值不能用於比較。** 請調低系統的麥克風輸入音量，
讓擊發峰值落在 -12 ~ -6 dBFS 之間再重新量測。

## 觸發記錄與 dwell time

擊發偵測分成三個狀態：

1. **待命** — 等待峰值跨過觸發閾值
2. **擷取中** — 跨過閾值後不立刻記錄，而是繼續收集 **dwell time** 毫秒，取這段期間的**最大值**才寫入記錄
3. **冷卻中** — 記錄後等待**再觸發間隔**，避免同一次擊發被記成多筆

dwell time 的意義：喀嗒聲的真正峰值通常落在跨過閾值之後幾毫秒，
若在跨越當下就記錄，量到的會是上升沿而不是真正的峰值，數值會系統性偏低。
預設 150 ms 足以涵蓋一次擊發的完整暫態與衰減；若擊發間隔很密可以調短，
但調得太短會漏掉真正的峰值。

| 參數 | 預設 | 範圍 | 說明 |
|---|---|---|---|
| 觸發閾值 | 0 dB | — | 峰值超過此值即開始擷取（單位為 dBFS，滿刻度是 0） |

預設值 0 是實測後依檢體針的實際判斷結果調整的，不是通用建議值——
不同麥克風、不同增益設定下，多大聲才算「有效擊發」會不一樣，
請依實際環境重新測試調整，不要照抄這個數字。

數字框旁邊的拖曳 bar（範圍 -80 ~ 0 dB）跟數字框互相同步，可直接拖動調整，
不必每次都手動輸入數字。若透過數字框輸入超出 bar 範圍的數值（例如校正後想用 dB SPL 表示），
數值本身照樣生效，只是 bar 不會跟著顯示。
| 量測窗 dwell | 150 ms | 10–5000 | 擷取窗長度，取窗內最大值 |
| 再觸發間隔 | 800 ms | 0–60000 | 記錄後的冷卻時間，設 0 表示不冷卻 |

記錄圖譜的縱軸在套用校正後會自動整組換算成 dB SPL，
橘色虛線為目前的觸發閾值。

## 即時讀值下方的趨勢圖

「即時讀值」下方原本是逐幀刷新的原始波形（像示波器），肉眼幾乎看不清楚在動什麼。
現在改成**近 1 分鐘的音量趨勢**：每 0.2 秒記一個點、視窗隨時間捲動，
變化速度看得清楚，也能看出緩慢的音量趨勢，不只是瞬間的雜訊。

- 橘色虛線是目前的觸發閾值
- 小三角形標記是視窗內發生過的擊發，紅色代表該筆削波
- 開始收音時會清空這張圖，重新從 0 秒累積

## 使用限制
本工具使用電腦內建或外接麥克風收音，屬於「相對比較」工具，**不是可追溯校正的聲學儀器**。
正式報告用的絕對 dB SPL 數值仍應使用 Class 1 噪音計 + 聲學校正器。

使用前請在瀏覽器／系統設定關閉麥克風的「自動增益 / 降噪 / 回音消除」，否則讀值會失真。

## 麥克風狀態指示燈

「開始收音」下方有一顆狀態指示燈，五種狀態直接對應瀏覽器實際偵測到的情況：

| 指示燈 | 意義 |
|---|---|
| 灰　麥克風未啟動 | 尚未授權，按下按鈕時瀏覽器才會詢問 |
| 淡綠　麥克風已授權，尚未啟動 | 權限已給過，按下按鈕即可開始 |
| **綠（閃爍）收音中** | 正常收音，有訊號進來 |
| 橘　已啟動 · 收不到訊號 | 拿到裝置了，但音訊樣本連續 0.5 秒完全是 0 |
| 紅 | 權限被拒絕／不是安全來源／裝置被移除或被其他程式接管／被系統靜音 |

橘色與紅色的差別很重要：橘色代表瀏覽器這一端都正常，問題出在裝置或系統設定；
紅色代表在拿到音訊之前就被擋住了。

## 自動偵測可用裝置

指示燈是橘色（已啟動但收不到訊號）時，按「自動偵測可用裝置」。
它會逐一開啟每個輸入裝置各收 1.2 秒、量測實際峰值，列出哪個裝置真的有聲音，
並自動選取訊號最強的那個。**掃描時請持續對麥克風發出聲音**，否則能用的裝置也會被判成靜音。

如果掃描結果是「所有輸入裝置都收不到訊號」，問題就不在瀏覽器，而在系統或硬體。
Windows 上依序檢查：

1. 筆電的**實體麥克風靜音鍵**（多數商用機在 F4／F8，機身或鍵盤上有麥克風圖示，通常帶指示燈）
2. 設定 → 隱私權與安全性 → 麥克風 → 「讓應用程式存取您的麥克風」及瀏覽器個別開關
3. 設定 → 系統 → 音效 → 輸入 → 選該裝置 → 音量不是 0、沒有靜音
4. 音效控制台 → 錄製 → 該裝置 → 內容 → 等級（有些驅動的「麥克風增強」預設為 0）
5. 關掉可能獨佔麥克風的程式（Teams、Zoom、錄音軟體）後重新整理頁面

## 收不到聲音時怎麼查

頁面啟動後，「開始收音」下方會顯示診斷列（裝置名稱、軌道狀態、AudioContext 狀態、取樣率、AGC/降噪/回音消除是否關閉）。依序確認：

| 症狀 | 代表什麼 | 怎麼處理 |
|---|---|---|
| 按下按鈕沒反應，顯示「不是安全來源」 | 用 `file://` 直接開本機檔案 | 改用 https:// 的網址開啟 |
| 顯示「麥克風權限為『拒絕』」 | 權限狀態 denied | 檢查 `chrome://settings/content/microphone`：**最上方的全域開關**是否為「網站可以要求使用您的麥克風」（若選「不允許」，所有網站都被拒且封鎖清單裡不會有條目），以及下方封鎖清單中是否有本站 |
| 顯示「權限提示未被允許（狀態仍為 prompt）」 | 提示跳出但沒被回答 | 再按一次開始收音，注意網址列正下方的小視窗並按「允許」；按 Esc 或點視窗外都算略過 |
| 顯示「系統層阻擋麥克風（瀏覽器權限是允許的）」 | 作業系統擋住，改瀏覽器權限沒用 | ① 筆電實體麥克風靜音鍵（多在 F4／F8）② Windows 設定 → 隱私權與安全性 → 麥克風 ③ 關閉獨佔麥克風的程式 |
| 顯示「麥克風被其他程式占用」 | NotReadableError | 關閉會議或錄音軟體後重新整理 |
| 顯示「音訊連續 2 秒完全是 0」 | 拿到裝置了但沒有訊號 | 換「輸入裝置」下拉選單試其他麥克風；檢查系統音效設定該裝置沒被靜音、音量不是 0；關掉可能獨佔麥克風的程式（會議軟體等） |
| 讀值停在 -100 附近不動 | 環境極安靜或增益太低 | 對著麥克風出聲測試；提高系統麥克風輸入音量 |
| 診斷列 AGC/降噪顯示「開」 | 瀏覽器沒接受關閉要求 | 到系統音效設定手動關閉該裝置的增強功能，否則讀值會失真 |
| 診斷列「波形擷取：不可用」 | 逐樣本擷取鏈建不起來 | 量測與自動記錄照常運作，只是沒有擊發波形；換用 Chrome/Edge 最新版通常可恢復 |

尚未開始收音時，診斷列會顯示瀏覽器回報的原始權限狀態（granted / prompt / denied），
可用來判斷卡在哪一層。開始收音後，診斷列最後一段顯示波形擷取使用哪一條路徑
（AudioWorklet / ScriptProcessor / 不可用）。
擷取鏈的建立刻意排在收音啟動**之後**且不等待其完成，
因此即使它失敗或逾時，收音、讀值與自動記錄都不受影響。
