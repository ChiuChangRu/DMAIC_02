# 檢體針噪音量測工具

瀏覽器端即時噪音量測工具（HTML + Web Audio API），用於評估檢體針觸發時的**相對**聲音大小。

線上使用：https://chiuchangru.github.io/DMAIC_02/

## 功能
- 即時 RMS 讀值 + Peak Hold（dBFS）
- 校正功能：輸入已知音壓（如聲學校正器 94 dB @ 1 kHz）換算近似 dB SPL
- 擊發自動觸發記錄（可調 dwell time 與再觸發間隔）+ 手動記錄，可匯出 CSV
- 記錄圖譜：每筆記錄畫成長條圖，同標籤同色，可直接比較不同針的相對音量

## 擊發波形與機構判讀

每次觸發除了記錄峰值，也會擷取擊發**前後**的完整波形（預設 -60 ~ +300 ms），
畫在「擊發波形」面板。點記錄表任一列可切換要看哪一次；
勾選「疊上同標籤的其他次」會把同一組的其他次擊發以淡線疊在同一張圖上，
共用縱軸尺度，可直接比對哪一次不一樣。

判讀重點：

- **t=0 之後出現第二個明顯脈衝** — 機構有二次撞擊或彈跳
- **主脈衝拖尾異常長** — 零件鬆動、共振
- **同一組之間波形形狀差異大** — 動作一致性不良
- **t=0 之前就有訊號** — 觸發閾值設太低，被環境噪音搶先觸發

擷取前／後的長度可在「觸發記錄設定」調整。波形僅存在瀏覽器記憶體中，
CSV 匯出只含數值欄位，重新整理頁面即消失。

### 削波（clipping）

樣本觸及數位滿刻度時，波形會被削平、峰值一律讀成 0.0 dBFS，
不同強度的擊發會變得完全無法區分。發生時：

- 主畫面出現紅色「⚠ 削波 CLIP」徽章（按「重置 Peak Hold」才會清除）
- 該筆記錄的「削波」欄標示 ⚠，圖譜上的長條加紅色頂蓋，CSV 該欄為 Y

**削波的數值不能用於比較。** 請調低系統的麥克風輸入音量，
讓擊發峰值落在 -12 ~ -6 dBFS 之間再重新量測。

## 觸發記錄與 dwell time

擊發偵測分成三個狀態：

1. **待命** — 等待峰值跨過觸發閾值
2. **擷取中** — 跨過閾值後不立刻記錄，而是繼續收集 **dwell time** 毫秒，取這段期間的**最大值**才寫入記錄
3. **冷卻中** — 記錄後等待**再觸發間隔**，避免同一次擊發被記成多筆

dwell time 的意義：喀嗒聲的真正峰值通常落在跨過閾值之後幾毫秒，
若在跨越當下就記錄，量到的會是上升沿而不是真正的峰值，數值會系統性偏低。
預設 150 ms 足以涵蓋一次擊發的完整暫態與衰減；若擊發間隔很密可以調短，
但調得太短會漏掉真正的峰值。

| 參數 | 預設 | 範圍 | 說明 |
|---|---|---|---|
| 觸發閾值 | -30 dB | — | 峰值超過此值即開始擷取 |
| 量測窗 dwell | 150 ms | 10–5000 | 擷取窗長度，取窗內最大值 |
| 再觸發間隔 | 800 ms | 0–60000 | 記錄後的冷卻時間，設 0 表示不冷卻 |

記錄圖譜的縱軸在套用校正後會自動整組換算成 dB SPL，
橘色虛線為目前的觸發閾值。

## 使用限制
本工具使用電腦內建或外接麥克風收音，屬於「相對比較」工具，**不是可追溯校正的聲學儀器**。
正式報告用的絕對 dB SPL 數值仍應使用 Class 1 噪音計 + 聲學校正器。

使用前請在瀏覽器／系統設定關閉麥克風的「自動增益 / 降噪 / 回音消除」，否則讀值會失真。

## 麥克風狀態指示燈

「開始收音」下方有一顆狀態指示燈，五種狀態直接對應瀏覽器實際偵測到的情況：

| 指示燈 | 意義 |
|---|---|
| 灰　麥克風未啟動 | 尚未授權，按下按鈕時瀏覽器才會詢問 |
| 淡綠　麥克風已授權，尚未啟動 | 權限已給過，按下按鈕即可開始 |
| **綠（閃爍）收音中** | 正常收音，有訊號進來 |
| 橘　已啟動 · 收不到訊號 | 拿到裝置了，但音訊樣本連續 0.5 秒完全是 0 |
| 紅 | 權限被拒絕／不是安全來源／裝置被移除或被其他程式接管／被系統靜音 |

橘色與紅色的差別很重要：橘色代表瀏覽器這一端都正常，問題出在裝置或系統設定；
紅色代表在拿到音訊之前就被擋住了。

## 自動偵測可用裝置

指示燈是橘色（已啟動但收不到訊號）時，按「自動偵測可用裝置」。
它會逐一開啟每個輸入裝置各收 1.2 秒、量測實際峰值，列出哪個裝置真的有聲音，
並自動選取訊號最強的那個。**掃描時請持續對麥克風發出聲音**，否則能用的裝置也會被判成靜音。

如果掃描結果是「所有輸入裝置都收不到訊號」，問題就不在瀏覽器，而在系統或硬體。
Windows 上依序檢查：

1. 筆電的**實體麥克風靜音鍵**（多數商用機在 F4／F8，機身或鍵盤上有麥克風圖示，通常帶指示燈）
2. 設定 → 隱私權與安全性 → 麥克風 → 「讓應用程式存取您的麥克風」及瀏覽器個別開關
3. 設定 → 系統 → 音效 → 輸入 → 選該裝置 → 音量不是 0、沒有靜音
4. 音效控制台 → 錄製 → 該裝置 → 內容 → 等級（有些驅動的「麥克風增強」預設為 0）
5. 關掉可能獨佔麥克風的程式（Teams、Zoom、錄音軟體）後重新整理頁面

## 收不到聲音時怎麼查

頁面啟動後，「開始收音」下方會顯示診斷列（裝置名稱、軌道狀態、AudioContext 狀態、取樣率、AGC/降噪/回音消除是否關閉）。依序確認：

| 症狀 | 代表什麼 | 怎麼處理 |
|---|---|---|
| 按下按鈕沒反應，顯示「不是安全來源」 | 用 `file://` 直接開本機檔案 | 改用 https:// 的網址開啟 |
| 顯示「無法取得麥克風：NotAllowedError」 | 瀏覽器權限被拒絕 | 點網址列左側的鎖頭圖示，把麥克風改成「允許」 |
| 顯示「音訊連續 2 秒完全是 0」 | 拿到裝置了但沒有訊號 | 換「輸入裝置」下拉選單試其他麥克風；檢查系統音效設定該裝置沒被靜音、音量不是 0；關掉可能獨佔麥克風的程式（會議軟體等） |
| 讀值停在 -100 附近不動 | 環境極安靜或增益太低 | 對著麥克風出聲測試；提高系統麥克風輸入音量 |
| 診斷列 AGC/降噪顯示「開」 | 瀏覽器沒接受關閉要求 | 到系統音效設定手動關閉該裝置的增強功能，否則讀值會失真 |
| 診斷列「波形擷取：不可用」 | 逐樣本擷取鏈建不起來 | 量測與自動記錄照常運作，只是沒有擊發波形；換用 Chrome/Edge 最新版通常可恢復 |

診斷列最後一段會顯示波形擷取使用哪一條路徑（AudioWorklet / ScriptProcessor / 不可用）。
擷取鏈的建立刻意排在收音啟動**之後**且不等待其完成，
因此即使它失敗或逾時，收音、讀值與自動記錄都不受影響。

## 注意事項
- 麥克風權限需要 HTTPS（GitHub Pages 已符合）或 localhost。
- 全部運算在瀏覽器本機執行，不上傳任何音訊。
